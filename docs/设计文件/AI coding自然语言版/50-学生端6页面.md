### Step B3: /opsx:apply（TDD 实现前端）

**操作**（在Claude Code中输入）：

```
/opsx:apply
```

**你应该看到**：Claude Code 按照 tasks.md 的顺序，以 TDD 方式实现所有功能：先写测试（全红）→ 生成实现代码 → 迭代修复 → 全部通过。Apply 会处理共享JS模块、6个页面、JWT认证、SSE流式对话、TabBar导航、所有交互状态机的全部实现。

**验证**：
- 确认 token 存储键名与后端 auth 模块一致
- 确认 SSE 流式解析正确覆盖设计文档定义的事件类型
- 确认 AI 对话的 persona 参数固定为 "student"
- 确认练习页的答案在切换题目时不丢失
- 确认错题本的手风琴逻辑——点击新卡片时先关闭当前展开再打开新卡片
- 确认"已掌握"按钮点击后卡片从 DOM 中移除
- 确认复习页与错题本的数据源不同（复习用到期复习接口，错题用错题列表接口）
- 确认绑定码生成后可复制
- 确认退出登录清除 token 后跳转登录页

**如果出错**：

| 错误 | 原因 | 解决 |
|------|------|------|
| requireAuth中JWT解析失败 | 未使用第三方JWT库 | 手动分割token的payload段并Base64解码，`JSON.parse(atob(token.split('.')[1]))` |
| SSE流中断 | LLM Provider超时或thread_id格式错误 | 检查Network面板SSE事件流，确认后端日志无异常 |
| 登录后CORS错误 | 后端CORS中间件未配置 | 确认main.py中CORS中间件允许前端开发服务器来源 |
| 练习页状态切换后数据丢失 | 状态变量在切换时被重置 | 将answers状态存储在render函数外部，使用闭包或全局state对象 |
| 错题本手风琴展开多个 | 未在展开新卡片前关闭旧的 | 在toggle逻辑中先循环关闭所有已展开的详情区，再打开当前 |
| 变式题按钮无响应 | 对应API端点未就绪 | 确认后端相应端点已实现并部署 |
| 复习页显示全量错题而非到期任务 | 错误使用了错题本的数据源 | 确认API端点为设计文档到期复习接口 |
| 绑定码生成返回错误 | 对应后端端点未实现 | 该功能依赖家长模块端点；在此之前返回mock数据或提示"即将上线" |
| 修改密码提交后无反馈 | 对应后端端点未实现 | 确认该端点已就绪，检查请求体格式 |

**Windows注意**：开发移动端页面时，Chrome DevTools按F12，然后Ctrl+Shift+M切换移动设备模拟，选择适合学生端的视口尺寸（参照35号文档响应式策略）。
