### Step A4: /opsx:apply（TDD 实现后端）

**操作**（在Claude Code中输入）：

**你应该看到**：Claude Code 按照 tasks.md 的顺序，以 TDD 方式实现所有后端功能：先写测试（全红）→ 生成实现代码 → 迭代修复 → 全部通过。Apply 会处理数据聚合API、预警引擎、定时调度、通知管道的全部实现。

**验证**：
- 确认 knowledge_points 按 error_rate 降序排列
- 确认 avg_score_trend 只包含设计文档中规定数量的最近考试数据点
- 确认 barrier_distribution 三项百分比之和接近 1.0
- 确认去重逻辑正确：同一 student_id + warning_type + pending 状态不重复创建
- 确认 APScheduler 注册了正确配置的定时触发器
- 确认通知管道向所有活跃绑定家长发送通知

**如果出错**：

| 错误类型 | 常见原因 | 排查方向 |
|----------|----------|----------|
| 知识点错误率计算不正确 | JSON 列在 SQLite 中模糊匹配困难 | 改用 Python 内存过滤：先查全部记录再 json.loads 判断 |
| 成绩趋势数据点数量异常 | 将无答题记录的考试也纳入了趋势 | 确认过滤条件：考试必须有答题记录才纳入 |
| 障碍分布归类不一致 | 对空值或 NULL 的处理不统一 | 确认空值情况下的默认归类策略一致 |
| JSON 字段查询失败 | SQLite 对 JSON 列支持有限 | JSON 包含查询统一在 Python 层面做过滤 |
| API 返回 404 | 路由注册顺序或路径参数命名问题 | 检查路由装饰器路径是否与设计文档一致 |
| 检测规则计算结果与预期不符 | 公式中分子分母顺序反了或基准值取错 | 对照设计文档第5.2节的数学公式逐项核对 |
| 去重测试失败 | 创建前未查询已有 pending 记录 | 创建前先 query：按 student_id、warning_type、status='pending' 过滤 |
| 时间比较测试不稳定 | mock 中用了本地时间而实现用了 UTC | 统一使用 UTC 时间，或在 mock 中固定时间点 |
| APScheduler 导入失败 | 依赖包未安装 | `pip install apscheduler` |
| 通知未推送给家长 | 家长绑定查询条件不完整 | 确认查询了 status='active' 的绑定关系 |
