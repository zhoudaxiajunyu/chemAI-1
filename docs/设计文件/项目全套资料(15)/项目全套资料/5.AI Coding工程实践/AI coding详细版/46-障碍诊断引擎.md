```

      │
      ├──→ LLM 深度诊断 ──────────→ LLM 诊断结果 (权重 0.4)
```

```yaml
rules:

    anti_keywords: []
```

**global配置**：min_keyword_match=2, min_pattern_match=1, confidence_base=0.85, keyword_weight=0.4, pattern_weight=0.6

**规则引擎匹配流程**：
1. 拼接 question_text + student_answer 为搜索文本
2. 遍历22条规则：keyword计数（大小写不敏感） + pattern正则匹配
3. keyword >= min_keyword_match 且 pattern >= min_pattern_match 时触发

5. anti_keywords命中则排除该规则

**融合算法核心逻辑**：
1. 提取规则引擎top_diagnosis置信度(rule_conf)和LLM第一条misconception置信度(llm_conf)
2. fused_conf = 0.6 * rule_conf + 0.4 * llm_conf，clamp到[0, 1]
3. 冲突检测：两路category不同 -> has_conflict = true
4. 冲突消解：rule_conf >= 0.85以规则为准；llm_conf >= 0.9以LLM为准；否则标记"需人工审核"
5. 置信度标签：<0.6 "low", 0.6-0.8 "medium", 0.8-1.0 "high"

```python
        f"融合置信度应 >= 0.80，实际 {final['confidence']:.3f}。" \

        "推荐练习应 >= 2 题"

    assert fused_result["llm_contribution"]["weight"] == 0.4
    assert fused_result["rule_contribution"]["matched_rules_count"] >= 1

    # 9. 输出诊断摘要
    print("=" * 60)
    print("端到端诊断结果 -- 勒夏特列原理案例")

    print(f"补救要点数: {len(fused_result['remediation']['rule_points'])}")
```

## 八、关键设计决策

### 为什么规则引擎权重 0.6 > LLM 权重 0.4？

化学迷思概念有明确的模式可循（学生反复犯的同类错误）。规则引擎在这些已知模式上的精确率约90%，显著高于LLM（存在幻觉风险）。但LLM覆盖了规则库未预见的边缘案例和语义变体，所以权重不为零。

### 为什么融合而非选一？

两条诊断路径互补 -- 规则引擎擅长已编目的已知模式（高精确率），LLM擅长语义理解和未见过的变体（高召回率）。融合利用各自的优势，在精确率和召回率之间取得平衡。

### 为什么用 YAML 配置而非数据库存储规则？

YAML 便于版本控制（git diff可读）、代码审查，且非程序员（化学教师）可以直接编辑添加规则。后续可通过 Admin 面板实现热重载。

```
       = 0.534 + 0.328
       = 0.862 -- 约87%
```
