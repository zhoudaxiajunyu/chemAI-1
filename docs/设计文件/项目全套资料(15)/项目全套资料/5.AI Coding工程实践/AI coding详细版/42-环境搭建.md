### Step 1: 安装 Node.js

**执行方式**：浏览器下载 + 终端验证

**你现在要做的是**：在你的电脑上安装 Node.js 运行环境（版本 18 或更高）。

**准备**：打开浏览器，访问 https://nodejs.org

**操作**：

打开浏览器，在地址栏输入 nodejs.org 并回车。网站会自动识别你的操作系统。点击页面上绿色的"LTS"按钮（长期支持版本），下载安装包。

下载完成后，双击安装包运行安装程序：

Mac用户：双击下载的 .pkg 文件，按照安装向导点击"继续"直到完成。

Windows用户：双击下载的 .msi 文件，按照安装向导操作。在安装过程中，确保勾选"Automatically install the necessary tools"选项，然后点击Next直到完成。

**你应该看到**：安装程序会显示进度条，最后显示"安装成功"或"Setup was successful"。

**验证**：

Mac用户打开"终端"（在应用程序 > 实用工具 > 终端），Windows用户打开"命令提示符"（按Win+R，输入cmd回车）。在终端中输入：

```
node --version
```

回车后你应该看到类似 v20.11.0 或 v22.x.x 的版本号。再输入：

```
npm --version
```

回车后你应该看到类似 10.2.4 的版本号。

**如果出错**：如果提示"command not found"或"不是内部或外部命令"，说明Node.js没有正确添加到系统PATH。Mac用户尝试关闭终端重新打开；Windows用户尝试重启电脑。如果仍然不行，重新运行安装程序。

**Windows注意**：安装完成后必须关闭并重新打开命令提示符，新的PATH才会生效。绝对不能跳过这一步。

### Step 2: 安装 Claude Code CLI

**执行方式**：终端命令

**你现在要做的是**：安装Claude Code命令行工具。如果你已经在使用Claude Code（比如现在），可以跳过安装步骤直接进入验证。

**准备**：确保Step 1已完成，Node.js版本 >= 18。

> **关于API Key**：本项目使用多个LLM提供商，按优先级：
> - **DashScope**（主力，阿里通义千问 qwen-turbo）— https://dashscope.aliyun.com
> - **DeepSeek**（备选，deepseek-chat）— https://api.deepseek.com
> - **MiMo-V2.5**（视觉/联网兜底，小米）— https://api.xiaomimimo.com
> - **智谱AI**（视觉分析备选）
> - **百度OCR**（答题卡识别）
>
> 全部通过 OpenAI 兼容 API 调用，在 `.env` 中配置各提供商的 API Key。
> 如果你使用 CC-Switch 等工具接入第三方模型，Claude Code 会自动使用其配置。

**操作**：

在终端中执行以下命令来全局安装Claude Code CLI：

```bash
npm install -g @anthropic-ai/claude-code
```

**你应该看到**：npm安装过程会显示下载进度条，最后显示"added X packages"表示安装成功。

**验证**：

```bash
claude --version
```

你应该看到版本号输出，类似 1.x.x。

然后再进行一次对话测试，确认Claude Code可以正常工作：

```bash
claude
```

等待几秒后，Claude Code会显示欢迎信息。然后输入以下消息并回车：

```
请用中文回复：你好，你现在能正常工作吗？
```

**你应该看到**：Claude Code会返回一行类似"你好！是的，我可以正常工作。"的回复。输入 `exit` 或按 Ctrl+C 退出交互模式。

**如果出错**：

| 错误 | 原因 | 解决 |
|------|------|------|
| `npm install` 失败，提示 `EACCES: permission denied`（Mac） | 全局安装需要权限 | 在命令前加 `sudo`：`sudo npm install -g @anthropic-ai/claude-code` |
| `npm: command not found` | Node.js未安装或PATH未生效 | 回到Step 1重新操作，确保安装后重启终端 |
| 安装后提示"claude不是内部或外部命令"（Windows） | PATH未刷新 | 关闭命令提示符重新打开，或者重启电脑 |
| `Authentication failed` 或 `Invalid API key` | API Key配置有误 | 执行 `claude config set apiKey YOUR_CORRECT_KEY` 重新配置 |
| `Network error` 或 `Connection refused` | 网络不通 | 检查网络连接。如果在公司/校园网络，可能需要配置代理：`claude config set httpProxy http://your-proxy:port` |
| 一直显示"Connecting..."不返回结果 | API服务繁忙 | 等待30秒后重试。按Ctrl+C取消，然后重新运行claude |

**Windows注意**：如果安装后提示"claude不是内部或外部命令"，关闭命令提示符重新打开，或者重启电脑。Windows的PATH更新有时需要重启资源管理器才会生效（最快的方法是重启电脑）。如果claude命令卡住没有任何输出，尝试用PowerShell代替命令提示符运行（在开始菜单搜索PowerShell）。

### Step 3: 安装 OpenSpec 并初始化项目

**执行方式**：终端命令 + Claude Code 验证

**你现在要做的是**：安装OpenSpec（规范驱动开发工具），用它初始化ChemAI项目的规格管理体系。

**准备**：确保Step 2已完成。Node.js版本 >= 20.19.0（OpenSpec要求）。

> **什么是OpenSpec**：一个专为AI编程设计的规范驱动开发（Spec-Driven Development）工具。核心理念是"先约定再动手"——把需求编码为Markdown规格文件，人类和AI Agent在写代码之前先在规格上对齐。工作流：`/opsx:propose` 创建变更提案 → `/opsx:apply` AI读规格生成代码 → `/opsx:archive` 完成后归档。

**操作**：

```bash
# 安装OpenSpec（官方包）
npm install -g @fission-ai/openspec@latest

# 创建并进入项目目录（chemai-backend 即项目根目录，后续所有步骤都在这里）
mkdir -p ~/chemai-project/chemai-backend && cd ~/chemai-project/chemai-backend

# 初始化OpenSpec项目
openspec init
```

初始化过程中：
- 按提示选择项目模板（选默认即可）
- OpenSpec会创建 `openspec/` 目录：`config.yaml`（项目配置）、`specs/`（当前规格）、`changes/`（变更提案）

**你应该看到**：

```
openspec/
├── config.yaml     # 项目配置（含 context: 字段，自动注入每次规划请求）
├── specs/          # 当前规格（系统的事实来源，随变更归档逐步积累）
└── changes/        # 活跃的变更提案
    └── archive/    # 已完成的变更（归档后自动创建）
```

> **注意**：旧版 OpenSpec 用 `project.md` 存项目上下文，现已迁移为 `openspec/config.yaml`。如果你看到的目录里没有 `config.yaml`，执行 `openspec update` 生成。`specs/`、`changes/archive/` 不是初始化时就建全的——第一次 propose 和 archive 时才会出现，这正常。

**验证**：

在Claude Code中输入以下指令，确认OpenSpec目录结构已正确创建：

```
请帮我确认 openspec/ 目录已创建，包含 config.yaml（若没有请执行 openspec update 生成）
```

此外，在终端中验证：

```bash
ls openspec/
openspec list
```

`openspec list` 应显示当前没有活跃变更（空项目）。

**如果出错**：

| 错误 | 原因 | 解决 |
|------|------|------|
| `npm ERR! 404 '@fission-ai/openspec' is not in this registry` | npm registry问题 | 让 Claude Code 切换到国内镜像源（如淘宝镜像 `npm config set registry https://registry.npmmirror.com`）后重试 |
| `Node.js version mismatch` — 要求 >= 20.19.0 | Node版本过低 | `node --version` 检查版本。如低于20.19.0，从 nodejs.org 下载LTS最新版覆盖安装 |
| `Permission denied`（Mac） | 全局安装需要权限 | 在命令前加 `sudo`，或配置npm prefix到用户目录 |
| `openspec init` 提示"directory not empty" | 当前目录已有文件 | 确保是在空目录中运行。如需重来：`rm -rf ~/chemai-project/chemai-backend` 后重新创建 |

**Windows注意**：强烈建议使用Git Bash执行以上命令。`openspec` 命令在Git Bash中完全可用。如果用CMD，路径使用反斜杠格式。

### Step 4: 安装 Gstack 技能包

**执行方式**：终端命令 + Claude Code 验证

**你现在要做的是**：安装Gstack——一套Claude Code的技能包（slash commands），提供50+个专用命令覆盖从规划到发布的全流程（数量随版本持续增长，以官方 `docs/skills.md` 清单为准）。

**准备**：确保Claude Code已安装（Step 2），Git已安装。

> **什么是Gstack**：Garry Tan（YC总裁）创建的Claude Code技能包。它把Claude Code变成一个"虚拟工程团队"——每个斜杠命令切换一个角色：
> - `/plan-ceo-review` — CEO视角的战略审查
> - `/plan-eng-review` — 工程经理的架构审查
> - `/review` — 代码审查
> - `/qa`、`/qa-only` — 浏览器自动化QA测试
> - `/ship` — 版本发布（合并+测试+changelog+PR）
> - `/retro` — 工程回顾
> - `/cso` — 安全审计
> - `/investigate` — 根本原因调试
> - 更多：`/browse`、`/design-html`、`/document-generate` 等共50+个

**操作**：

```bash
# 克隆Gstack到Claude Code技能目录
git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/.claude/skills/gstack

# 运行安装脚本
cd ~/.claude/skills/gstack && ./setup
```

**你应该看到**：setup脚本执行后，`~/.claude/skills/gstack/` 目录下出现50+个SKILL.md文件和其他配置（数量以官方仓库为准）。

**验证**：

在Claude Code中输入：

```
请在Claude Code中输入 / 查看自动补全列表，确认Gstack命令（/qa、/ship、/retro等）已出现
```

Claude Code输入 `/` 后应该能看到 `/qa`、`/ship`、`/retro`、`/review`、`/plan-ceo-review` 等Gstack命令。

也可以执行终端命令验证文件存在：

```bash
ls ~/.claude/skills/gstack/ | head -20
```

**如果出错**：

| 错误 | 原因 | 解决 |
|------|------|------|
| `git clone` 失败（网络问题） | GitHub不可达 | 尝试使用代理或镜像：`git clone https://ghproxy.com/github.com/garrytan/gstack.git` |
| `./setup: Permission denied` | 脚本没有执行权限 | `chmod +x setup && ./setup` |
| `./setup` 报错缺少Bun | Gstack部分功能需要Bun运行时 | `curl -fsSL https://bun.sh/install | bash` 安装Bun后重试 |
| Claude Code输入 `/` 看不到Gstack命令 | 安装路径不对或Claude Code未重启 | 确认文件在 `~/.claude/skills/gstack/` 下，重启Claude Code |
| Windows Git Bash中 `./setup` 不执行 | Windows路径问题 | 在Git Bash中运行：`bash setup` |

**Windows注意**：Gstack在Windows上的Git Bash中完全可用。Bun在Windows上可能需要WSL。如果Bun不可用，Gstack的大多数Skill仍然可以通过Claude Code正常工作（只有少数需要Bun编译的功能受影响）。

### Step 4.3: 安装 no-mistakes 门禁（每次 push 的安全闸门）

**执行方式**：Claude Code 对话

**你现在要做的是**：安装 no-mistakes——一个独立的 pre-push 门禁工具。它会在你 `git push` 时自动跑一遍 review → test → docs → lint 流水线，全绿才把代码推上去。**从文档 43 起，每次推送都会用到它**（59 发布时做最终确认）。

> **大白话**：no-mistakes 是挡在"推送"前面的保安。AI 写的代码想推到远端，先过保安这一关；保安让另一个 AI 帮你复查、跑测试、查文档、查格式，全部通过才放行。它和 Gstack 是两套东西——Gstack 是"工程团队角色"，no-mistakes 是"推送闸门"。

**在 Claude Code 中输入**：

```
帮我安装 no-mistakes 门禁工具：先 curl -fsSL https://raw.githubusercontent.com/kunchenguid/no-mistakes/main/docs/install.sh | sh 安装，然后在当前项目里执行 no-mistakes init（它会自动在用户级安装 /no-mistakes 技能）。装完验证 no-mistakes --version 可用。
```

**你应该看到**：安装脚本输出 + `no-mistakes init` 提示 "Gate initialized" + 版本号。此后 `git push no-mistakes` 即可走门禁流水线。

**如果出错**：

| 错误 | 原因 | 解决 |
|------|------|------|
| 安装脚本下载失败 | 网络问题 | 告诉 Claude Code：`帮我用代理或镜像重试，或者用 go install 方式安装` |
| `no-mistakes` 命令找不到 | PATH 未刷新 | 关闭终端重新打开，或让 Claude Code 处理 PATH |

### Step 5: 创建项目骨架

**执行方式**：Claude Code 对话

**你现在要做的是**：在Claude Code中一次性完成四件事——创建目录结构、创建CLAUDE.md（项目行为准则）、创建CONTEXT.md（领域词汇表）、创建DESIGN.md（前端视觉设计规范）。

**准备**：确保你在 `~/chemai-project/chemai-backend` 目录中（这是项目根目录，目录内应已有 openspec/），且Step 3已完成（OpenSpec已初始化）。

**操作**：

在Claude Code中输入以下完整指令：

```
请帮我创建项目目录结构（当前目录即项目根目录 chemai-backend），包含 app/、tests/、agent/ 等子目录。然后创建 CLAUDE.md（项目行为准则）和 CONTEXT.md（领域词汇表）。注意：目录结构、CLAUDE.md、CONTEXT.md、DESIGN.md 四件套全部放在当前目录（项目根目录）下，不要在项目内再嵌套一层 chemai-backend 或 backend 子文件夹。

CLAUDE.md参考总体开发方案中的工具链和流程设计，包含以下核心内容：

1. 项目背景：ChemAI（智辅化学）是一个AI驱动的中学化学教学辅助平台，目标用户是中国初中和高中化学教师、学生及家长。核心功能包括AI Agent对话系统、出题工作台、四维审核引擎、障碍诊断引擎、题库管理与考试生命周期、学生练习与错题本、家长端。技术栈为 Python 3.11+ / FastAPI / SQLAlchemy / SQLite / ChromaDB，AI层使用 LangGraph + 多LLM提供商（主力 DashScope 通义千问 qwen-turbo，备选 DeepSeek deepseek-chat，MiMo-V2.5 承担视觉/联网兜底，全部走 OpenAI 兼容 API），教师端前端为 React 19 + Vite + antd 组件化 SPA，学生/家长端为移动优先轻量页面（详见设计文档 37 技术选型）。

2. 行为准则（4条核心原则）：
   - 先思考再编码：开始实现前明确陈述假设，不确定时发问
   - 简单优先：只写解决问题所需的最少代码
   - 手术式修改：只触及必须修改的代码，匹配已有风格
   - 目标驱动执行：将任务转化为可验证的目标

3. 项目特定规范：
   - 所有代码注释和文档使用中文
   - Python代码遵循PEP 8
   - 数据库模型使用SQLAlchemy ORM
   - API遵循RESTful设计
   - 使用TDD（测试驱动开发）
   - 化学方程式使用LaTeX格式：$...$包裹
```
