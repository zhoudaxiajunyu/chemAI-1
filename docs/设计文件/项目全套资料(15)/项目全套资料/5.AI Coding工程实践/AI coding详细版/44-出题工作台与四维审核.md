### Step 2: 实现后端四维审核 API（FastAPI + SQLAlchemy）

**说明**：后端已有 `app/api/question.py` 包含题目生成和审核的基础设施。本步骤扩展四维审核专用 API 端点，完善审核工作流。

**需要实现的 API 端点**（文件：`app/api/review.py`）：

| 端点 | 方法 | 用途 |
|------|------|------|
| `/api/review/submit` | POST | 提交题目进入四维审核（创建四维度评分记录） |
| `/api/review/{question_id}` | GET | 获取某道题的四维审核结果 |
| `/api/review/{question_id}/approve` | POST | 审核通过（更新 audit_status → passed） |
| `/api/review/{question_id}/reject` | POST | 审核驳回（更新 audit_status → blocked，记录驳回原因） |

**模型说明**（来自 `app/models/database.py`）：

```python
class AuditStatus(PyEnum):
    PASSED = "passed"    # 审核通过
    WARNING = "warning"  # 有问题但不阻碍使用
    BLOCKED = "blocked"  # 审核不通过，需要修改

class Question(Base):
    __tablename__ = "questions"
    question_id = Column(String(64), primary_key=True)
    content = Column(Text, nullable=False)         # 题目正文
    options = Column(JSON, nullable=True)           # 选项列表 ["A. x", "B. x"]
    answer = Column(String(256), nullable=True)     # 参考答案
    analysis = Column(Text, nullable=True)          # 题目解析
    knowledge_points = Column(JSON, nullable=True)  # 知识点标签列表
    difficulty = Column(Enum(Difficulty), default=Difficulty.MEDIUM)
    source = Column(Enum(QuestionSource), default=QuestionSource.AI_GENERATED)
    audit_status = Column(Enum(AuditStatus), default=AuditStatus.PASSED)
    audit_report = Column(JSON, nullable=True)      # 四维审核报告
    # 审核维度
    coefficient_correct = Column(Boolean, default=True)  # 系数配平
    condition_correct = Column(Boolean, default=True)    # 反应条件
    product_correct = Column(Boolean, default=True)      # 产物正确性
    structure_correct = Column(Boolean, default=True)    # 分子结构
```

**四维审核维度**（化学题目专用）：

| 维度 | 字段 | 含义 | 审核方式 |
|------|------|------|---------|
| 系数配平 | `coefficient` | 化学方程式左右原子数是否相等 | `chemical_balance.py` 自动检测 |
| 反应条件 | `condition` | 反应条件（加热、催化剂、压强等）是否正确 | LLM 语义判断 |
| 产物正确性 | `product` | 反应物和生成物是否有化学事实错误 | LLM 语义判断 |
| 分子结构 | `structure` | 有机分子结构式/官能团是否正确 | LLM 语义判断 |

| `marked is not defined` | marked 依赖未安装 | `npm install marked`，确认组件内正确的 `import marked from 'marked'` |
| API 返回 401 | 未登录 | 先访问 `/login.html` 登录获取 token |

### Step 4: 实现审核工作流状态机

**说明**：实现审核工作流纯函数模块 `app/services/review_workflow.py`，定义题目的审核状态转换规则。

**状态定义**（来自 `app/models/database.py` 的 `AuditStatus` 枚举）：

```
DRAFT ──(提交审核)──> PENDING_REVIEW ──(通过)──> PASSED
                         │
                         ├──(驳回)──> BLOCKED
                         │              │
                         └──(重新提交)──┘
```

**状态转换表**：

| 当前状态 | 允许的目标状态 | 守卫条件 |
|---------|--------------|---------|
| `draft` | `pending_review` | 四个维度全部评分 |
| `pending_review` | `passed` | 审核意见 >= 10字 且 综合评分 >= 60 |
| `pending_review` | `blocked` | 驳回理由 >= 10字 |
| `blocked` | `pending_review` | 重新提交（题目已修改） |
| `passed` | `pending_review` | 题目内容修改后重新申请审核 |

**TDD 流程**：

1. **用户编写测试**（在 Claude Code 中输入）：

```
请编写 pytest 测试 tests/test_review_workflow.py：

测试用例（workflow 纯函数，无需数据库）：
"状态转换规则"(6):
- draft 可转到 pending_review
- pending_review 可转到 passed（需审核意见>=10字）
- pending_review 可转到 blocked（需驳回理由>=10字）
- blocked 可转回 pending_review
- passed 可回退到 pending_review
- draft 不可跳过审核直接 passed

"守卫条件"(5):
- draft → pending_review 需四个维度全部评分，缺一则失败
- pending_review → passed 需综合评分>=60，<60 则失败
- pending_review → rejected 驳回理由<10字则失败
- 驳回理由>=10字时成功
- 综合评分<60时不能通过

"批量审核"(4):
- 批量提交审核全部成功
- 批量通过审核
- 任一失败则全部不执行（事务性回滚）
- 空列表操作返回空成功
```

2. **Claude 生成实现**：创建 `app/services/review_workflow.py`。

3. **运行验证**：

```bash
pytest tests/test_review_workflow.py -v
# 预期全部通过
```

**提示词示例**（在 Claude Code 中输入）：

```

1. ALLOWED_TRANSITIONS 状态转换表（dict）：
   - "draft" → ["pending_review"]
   - "pending_review" → ["passed", "blocked"]
   - "blocked" → ["pending_review"]
   - "passed" → ["pending_review"]

2. transition(current_status, target_status, context) → dict：
   - 检查转换是否在允许列表中
   - 守卫条件：
     - draft → pending_review: 需四个维度全部评分
     - pending_review → passed: 需审核意见 >= 10字 且 total_score >= 60
     - pending_review → blocked: 需驳回理由 >= 10字
   - 返回 {"success": bool, "message": str, "new_status": str}

3. batch_transition(items, target_status) → list[dict]：
   - 事务性：先校验所有项，全部通过再统一执行
   - items: [{"current": str, "context": dict}, ...]
   - 返回: [{"success": bool, "message": str, "new_status": str}, ...]

   - 检查四个维度是否都 > 0

```

| 状态转换类型错误 | 枚举值字符串与 dict key 不匹配 | 统一使用字符串值 `"draft"`, `"pending_review"` 等 |
| 中文长度判断 | `len("驳回")` = 2，而非1 | Python 中中文每个字符长度为 1，直接用 `len(reason)` 即可 |
