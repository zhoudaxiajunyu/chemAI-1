# 00-Vibe Coding. ChemAI 实践指南

> 这份文档是"vibe coding"版本——你不需要学完整的工程化工具链（TDD 循环、Evals 基线对比、分支策略这些），只需要会用 **5 个最常用的技能命令**（见"技能包"一节）+ 跟 AI 对话。
>
> 对应标准版 `00-总体开发方案.md` 的 7 个阶段，本指南将全部转化为自然语言 prompt。你可以把这份文档当作"跟 AI 聊天就能把项目做出来"的操作手册。

---

## 什么是 Vibe Coding

Vibe coding 的核心思想：**你描述想要什么，AI 负责怎么实现**。

传统工程化流程是：写规格文档 → 设计架构 → 写测试 → 写代码 → 跑测试 → 审查 → 合并。但在 vibe coding 里，这些步骤压缩成一句话：

> "帮我做一个化学题库管理系统，老师可以出题、组卷、考试，学生可以答题、看解析，家长可以看到学情报告。用 Python FastAPI + Vue3。"

然后你跟 AI 反复对话，逐步把东西做出来。

两种方式的对比如下（简易版不是"零工具"，而是**只用 5 个最常用的命令 + 大量对话**，见下一节"技能包"）：

| 维度 | 标准版（完整工程化） | 简易版（vibe + 少量技能） |
|------|-----------|-------------|
| 启动方式 | `/opsx:propose` 创建规格提案 | `/opsx:propose` 或直接"帮我做一个..." |
| 开发节奏 | TDD 循环：写测试→AI生成→验证 | "把这个功能做了，顺便写几个测试" |
| 质量保证 | L1/L2/L3 Evals + 基线对比 | `/qa` 让 AI 自己点一遍网站 + "跑一下测试" |
| 版本管理 | Conventional Commits + 分支策略 | "帮我把这个改动提交了" |
| 发布 | `/ship` 灰度 → `/retro` 复盘 | `/ship` 一条龙 + "帮我部署到服务器上" |
| 修复 bug | `/investigate` 诊断流程 | "这里有个 bug，帮我看看怎么回事" |
| 迭代方式 | 规格驱动，一次通过 | 多轮对话，逐步打磨 |

**适合 vibe coding 的场景**：
- 个人项目、MVP、原型验证
- 你大概知道要做什么但不想被工程流程拖慢
- 你更擅长描述业务而不是写代码

**不适合 vibe coding 的场景**：
- 多人协作的大型项目（需要统一的规格和流程）
- 对可靠性有严格要求的系统（金融、医疗等）
- 需要合规审计的项目

## 技能包：给 AI 装外挂（大白话）

Vibe coding 不等于"只会聊天"。你可以给 Claude Code 装几个**技能包**（skills），让 AI 多出几个"专业身份"。装完之后，你在对话里输入 `/命令`，AI 就会切换到对应的工作模式。本指南只用到 5 个命令，每个都用大白话解释：

| 命令 | 来自 | 大白话 | 什么时候用 |
|------|------|--------|-----------|
| `/opsx:propose` | OpenSpec | "先写需求纸条再动手"——AI 先把你说的需求写成一张规格纸条（proposal），你确认了它才开工 | 每个功能开始前 |
| `/opsx:apply` | OpenSpec | "照着纸条干活"——AI 按刚才确认的规格逐条实现，每完成一条打一个勾 | propose 之后 |
| `/qa` | Gstack | "让 AI 当测试员"——AI 打开浏览器把你的页面从头点一遍，找出问题并修掉 | 功能做完后 |
| `/code-review` | Matt 技能包 | "让 AI 当审查员"——AI 从两个角度检查代码：写得规不规范、有没有实现你要的功能 | 提交合并前 |
| `/ship` | Gstack | "让 AI 当发布员"——合并代码、跑测试、升版本、写更新日志、开 PR，一条龙 | 全部做完要发布时 |

**安装**（只装一次）：装好 Claude Code 后，让它帮你装这三个技能包：

```
帮我安装三个技能包：OpenSpec（npm install -g @fission-ai/openspec）、Gstack（clone https://github.com/garrytan/gstack.git 到 ~/.claude/skills/gstack 并跑 setup）、Matt Pocock 的 skills 插件（claude plugin marketplace add mattpocock/skills 后安装）。装完验证 /opsx:propose、/qa、/code-review 都能用。
```

> **为什么用技能包而不是纯聊天？** 纯聊天像让 AI"自由发挥"，技能包像给 AI"套上工作流程"。`/opsx:propose` 保证它先听清楚需求再写代码，`/qa` 保证它自己先测一遍再交给你——这些是 vibe coding 最容易翻车的环节，用命令兜底最省心。

## 项目概览：ChemAI 化学自适应学习平台

在开始之前，先用一句话让 AI 理解整个项目：

> "我要做一个叫 ChemAI 的化学自适应学习平台。核心功能是：老师能创建题库、组卷出题、管理考试；学生能在线答题、看到 AI 诊断自己的薄弱点、做自适应练习、间隔复习；AI 能批改答题卡（OCR）、生成学情报告；家长端能看到孩子的学习报告。技术栈用 Python FastAPI 后端 + Vue3 前端 + SQLite 数据库。整个项目通过跟 Claude Code 对话开发。"

这句话就是你的"项目 prompt"，把它发给 Claude Code，AI 就有了全局认知。

> **重要：设计文档是本项目的规格来源。** Part 4 产品设计目录（`../4.产品设计/`）下有 20+ 份详细的设计文档，定义了每个功能的 ER 图、交互流程、API 设计、评测体系等。**每个阶段的 prompt 都会引导 AI 先阅读对应的设计文档，再开始写代码。** 不要让 AI 凭空想象——把设计文档当作"需求规格说明书"喂给它。
>
> **简化说明**：简易版使用简化的页面路由（`/workbench`、`/exam-banks`、`/practice` 等），与设计文档的页面结构（`frontend/pages/*.html`）不完全一致——demo 阶段够用就行，想对齐真实结构请看"详细版"。

ChemAI 项目分为 7 个阶段。下面每个阶段都给出现成的 prompt，你只要复制粘贴到 Claude Code 里就行。

## 阶段一：环境搭建

**目标**：装好工具，搭好项目骨架。

### 你只需要装的
1. **Node.js**（版本 >= 18）：浏览器打开 nodejs.org，下载 LTS 版，一路下一步
2. **Claude Code**：终端输入 `npm install -g @anthropic-ai/claude-code`
3. **Python**（版本 >= 3.10）+ Git：装好就行
4. **技能包**（OpenSpec + Gstack + Matt 插件）：安装指令见上面"技能包"一节，直接复制粘贴给 Claude Code 让它帮你装

### 开始对话

装好 Claude Code 后，在终端输入 `claude` 进入对话模式，然后依次发以下 prompt：

**Prompt 1：初始化项目**
```
帮我创建一个 ChemAI 项目。创建 chemai-backend/ 目录，初始化 Python 项目（虚拟环境、FastAPI 骨架），写一个最简单的 main.py 能返回 "ChemAI API is running"。同时创建 CLAUDE.md 记录项目信息：这是一个化学自适应学习平台，技术栈 Python FastAPI + Vue3 + SQLite，通过 Claude Code 对话开发。
```

**Prompt 1.5：初始化仓库和规格体系（很重要，别跳过）**
```
帮我做三件事：
1. 初始化 git 仓库（git init），创建 .gitignore（忽略 venv/、__pycache__/、.env、*.db）
2. 运行 openspec init 初始化规格体系（后续 /opsx:propose 命令依赖它；如提示需要安装，先 npm install -g @fission-ai/openspec）
3. 把当前骨架提交到 git：commit message 用 "chore: initial project scaffold"
```

> **为什么必须做 Prompt 1.5**：`/opsx:propose` 需要一个已初始化的 `openspec/` 目录才能工作；git 仓库是后面所有"提交/回退"操作的前提——这两个不装好，后面的技能包命令都会报错。

**Prompt 2：确认一切就绪**
```
帮我验证环境：确认 Python 版本 >= 3.10，pip 可用，虚拟环境已创建，FastAPI 已安装，启动 uvicorn 后能访问 http://localhost:8000/ 看到 "ChemAI API is running"。
```

如果 AI 说哪里不对，继续跟它对话直到修好。这就是 vibe coding 的方式——不写操作手册，直接让 AI 帮你搞定。

## 阶段二：数据模型 + 认证体系

**目标**：建好数据库表，实现登录认证，设置权限。

### Prompt

> **技能包用法**：从本阶段开始，每个功能先让 AI"写需求纸条"再动手。在输入下面的 Prompt 3 之前，先跑一次 `/opsx:propose`：

```
/opsx:propose 实现数据模型与认证体系：SQLAlchemy 模型（学校/年级/班级/题库/题目/考试/诊断/复习/家长）、JWT 登录、三种角色权限
```

AI 会先产出 proposal（为什么做）+ specs（需求）+ design（方案）+ tasks（任务清单）。你扫一眼纸条内容没问题，就让它继续：先输入 `/opsx:apply`（照着纸条干活），把下面 Prompt 3-5 的具体要求作为补充说明发给它。

**Prompt 3：创建数据模型**
```
先阅读设计文档 ../4.产品设计/33-数据模型设计.md，理解 ER 图、17 个实体关系、枚举定义和 JSON 字段 Schema。然后帮我设计 ChemAI 的数据模型。需要支持以下业务：
1. 学校/年级/班级体系：School → Grade → Class，学生和老师分别关联到学校和班级
2. 题库系统：题库(ExamBank)里有题目(Question)，题目分题型(选择/填空/计算/实验)，有难度等级，有知识点标签
3. 考试系统：试卷(ExamPaper)包含多道题，考试记录(ExamRecord)记录学生的每次考试，包含得分和每道题的作答
4. 诊断系统：诊断报告(Diagnosis)记录学生的薄弱知识点和学习建议
5. 复习系统：间隔复习计划(ReviewPlan)和错题本(WrongBook)
6. 家长系统：家长账号绑定学生，能查看学情报告

用 SQLAlchemy 定义所有模型，写入 app/models.py。同时用 Alembic 做数据库迁移。数据库用 SQLite。
```

**Prompt 4：加上认证**
```
帮我实现用户认证系统：
1. 支持老师、学生、家长三种角色登录
2. 用 JWT 做 token 认证（用 python-jose 库实现，不要自己手写 JWT——手写容易出安全漏洞）
3. 不同角色有不同的权限：老师能管理题库和考试，学生只能做题和看自己的报告，家长只能看绑定的孩子的报告
4. 创建认证中间件，保护需要登录才能访问的 API

把认证逻辑写在 app/auth.py，中间件写在 app/middleware/auth.py。
```

**Prompt 5：写测试**
```
帮我给刚才创建的模型和认证逻辑写测试。用 pytest，测试覆盖：每个模型的 CRUD 操作、字段约束、外键关联、JWT token 生成和验证、权限检查。测试文件放在 tests/ 目录下。写完后跑一遍确认全部通过。
```

做完后跟 AI 说：**"帮我把当前的改动提交到 git，写个清楚的 commit message。"**

**目标**：老师能出题、管题库、看学生诊断报告。

### Prompt

**Prompt 6：出题工作台**
```
先阅读设计文档 ../4.产品设计/24-AI出题与题库管理系统设计.md 和 ../4.产品设计/25-四维安全审核引擎设计.md，理解出题工作台的功能定义、四维审核机制和交互流程。然后帮我做出题工作台。老师登录后能在浏览器里看到出题界面，功能包括：

1. 创建题库：老师可以创建多个题库（如"高一化学期中题库"、"高二有机化学题库"）
2. 题库操作：往题库里添加题目、移除题目、调整顺序
3. 题库列表：查看所有题库，每个题库显示题目数量和创建时间

1. 哪些知识点掌握得好，哪些薄弱
2. 薄弱原因分类：概念不理解 / 计算错误 / 审题失误 / 知识遗忘
3. 给出具体的学习建议和推荐练习题
4. 诊断报告可视化：用图表展示学生的知识掌握热力图

> **技能包用法**：出题工作台做完后，让 AI 当一次测试员——输入 `/qa`，它会打开浏览器把页面从头点一遍：

```
/qa http://localhost:8000/workbench
```

（把地址换成你实际的前端页面地址。AI 会找出点不了的按钮、报错的接口，并顺手修掉。）

## 阶段四：业务功能（练习 + 学情 + OCR + 学生端 + 家长端）

**目标**：学生能用，家长能看到，AI 能批改答题卡。

### Prompt

**Prompt 9：自适应练习**
```
先阅读设计文档 ../4.产品设计/27-自适应练习引擎设计.md，理解 ZPD 最近发展区模型、barrier 到策略的映射矩阵和难度调节算法。然后帮我做自适应练习系统。根据学生的诊断结果（薄弱知识点），自动生成个性化练习题：
1. 从薄弱知识点开始练习
2. 做对了逐步提高难度，做错了给出解析并降低难度
3. 记录每次练习的结果，更新学生的知识掌握模型

## Vibe Coding 实战心法

这份文档的 prompt 是"理想路径"，真实开发中你会反复遇到以下情况，这完全正常：

### 1. 一个 prompt 很少一次就完美

```
你："帮我做题库管理系统"
AI：生成了一堆代码
你："不对，我要的是老师能分享题库给其他老师"
AI：改了
你："筛选功能也不对，应该能按知识点和难度同时筛选"
AI：又改了
你："差不多了，提交吧"
```

这是正常的。平均一个功能需要 2-5 轮对话。不要期望一次完美。

### 2. 改了 A 功能可能会搞坏 B 功能

```
你："把题库的搜索逻辑优化一下"
AI：改了
你跑测试 → 3 个考试相关的测试挂了
你："刚才改题库搜索把考试模块的测试搞挂了，修一下"
AI：修好了
```

每次大改动后，说一句 **"帮我跑一遍测试看有没有问题"**，养成这个习惯能省很多时间。

### 3. AI 的代码有时候能用但不够好

```
AI 写的代码能跑，但是：
- 没有错误处理："老师删题库时如果题库有题目呢？"
- N+1 查询："加载题库列表时每个题库都单独查一次题目数量，100 个题库就查 100 次"
- 安全性："学生 ID 直接拼在 URL 里，换个 ID 就能看别人的成绩"

这时追加 prompt：
- "加上边界情况处理"
- "这个查询太慢了，优化一下，用 JOIN 一次查出来"
- "加上权限检查，学生只能看自己的数据"
```

### 4. 让 AI 帮你理解它写的代码

```
你："你刚才写的诊断引擎逻辑我看不太懂，用简单的中文解释一下"
AI：解释了
你："那个薄弱度评分公式能展开讲讲吗"
AI：展开了
```

不要怕问。vibe coding 的核心就是对话——你不需要自己读代码，让 AI 读给你听。

### 5. 善用 git 做"存档点"

每次一个功能能跑通后：

```
"帮我把当前改动提交到 git，message 写清楚改了什么"
```

这样如果后面改坏了，随时可以：
```
"帮我回退到上次提交的状态"
```

不需要记 git 命令，让 AI 帮你操作就行。
