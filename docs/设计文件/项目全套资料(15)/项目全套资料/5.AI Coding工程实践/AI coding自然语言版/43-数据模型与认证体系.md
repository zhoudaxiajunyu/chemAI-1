**目的**：OpenSpec apply 自动按照 tasks.md 的顺序逐条实现，替代原来 Step 2-8 中所有零散的 Claude 提示词。apply 会先写测试、再写实现、跑通后进入下一条任务。

**基础设施常见问题**（apply 过程中可能出现）：

| 问题                               | 原因                              | 方向                                                           |
| -------------------------------- | ------------------------------- | ------------------------------------------------------------ |
| pytest 找不到测试文件                   | 文件名不以 `test_` 开头或不在 `tests/` 目录 | 确认命名符合 pytest 发现规则                                           |
| `fixture 'db_session' not found` | `tests/conftest.py` 缺失          | 需要创建 conftest.py，实现 SQLite 内存引擎 + create_all + yield session |
| JSON 字段读取为字符串                    | SQLite 不原生支持 JSON               | 引擎创建时配置 `json_serializer/json_deserializer`                  |
| 外键约束失败                           | 测试中未按依赖链顺序创建父表记录                | fixture 创建顺序要跟模型依赖链一致                                        |

**Alembic常见错误速查**：

| 错误                                            | 原因                        | 解决                                        |
| --------------------------------------------- | ------------------------- | ----------------------------------------- |
| `Target database is not up to date`           | 存在未执行的迁移版本                | 先执行 `alembic upgrade head` 再重新生成          |
| `Can't locate revision identified by 'xxxxx'` | alembic版本链断裂              | 备份后删除 `alembic_version` 表重新生成             |
| `table XXX already exists`                    | 表名冲突                      | 删除SQLite数据库文件后重新运行 `alembic upgrade head` |
| autogenerate检测到不期望的变更                         | default/nullable属性与数据库不一致 | 人工审查迁移脚本，删除不期望的操作                         |

### Step 5.2: 认证端点实现（login / refresh）

> **为什么必须有**：本阶段定义了 JWT 方案、认证中间件和 RBAC 权限矩阵，但没有"登录拿 token"的端点实现步骤——中间件没有 token 可校验，58 号文档第一步（打开登录页、登录成功）就断链。34 号文档已定义这两个端点，本 Step 确认它们被实现并有测试覆盖。

**在 Claude Code 中输入**：

```
/opsx:apply 除 tasks.md 中的任务外，请确认 34 号文档定义的认证两端点已实现并测试（若 tasks.md 漏了，请补充实现）：
1. POST /api/auth/login：username + password → passlib bcrypt 校验密码哈希 → 签发 access_token（24h）+ refresh_token（7d），HS256；成功响应按 34 号文档"POST /api/auth/login"：success/token/refresh_token/user_id/name/role；密码错误返回 401
2. POST /api/auth/refresh：用 refresh_token 换新 access_token，过期或伪造返回 401
3. 测试覆盖：正确登录 200 / 错误密码 401 / 伪造或过期 token 401 / refresh 换发成功
```

**验证**：`python -m pytest -k auth` 全绿；用 /docs（Swagger）实测一次登录，拿 token 调用一个受保护接口（如账号信息）返回 200。

**如果出错**：

| 错误方向                   | 排查思路                                                                         |
| ---------------------- | ---------------------------------------------------------------------------- |
| passlib 与 bcrypt 版本不兼容 | `pip install passlib[bcrypt]==1.7.4`（bcrypt 4.x 需 1.7.4+），或直接改用 `bcrypt` 库校验 |
| 密码正确仍返回 401            | 检查是否用 `pwd_context.verify` 对同一哈希值校验，确认存储的哈希字段未截断                             |
| token 校验失败             | 检查 SECRET_KEY 在签发与校验两侧一致，算法为 HS256                                           |
| 与 34 号文档响应字段不一致        | 以 34 号"POST /api/auth/login"的成功响应字段为准                                        |

**提交**（在Claude Code中输入）：请帮我提交当前的更改。先 git status 确认变更范围，选择属于同一个逻辑变更的文件，使用 Conventional Commits 格式提交。
