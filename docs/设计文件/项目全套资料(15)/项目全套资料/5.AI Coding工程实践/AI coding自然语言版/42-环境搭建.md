### Step 1: 安装 Node.js

**执行方式**：Claude Code 对话

**你现在要做的是**：确保电脑上安装了 Node.js 运行环境（版本 20.19.0 或更高，OpenSpec 的要求）。如果还没装，Claude Code 会告诉你具体怎么装。

**在 Claude Code 中输入**：

```
帮我检查 Node.js 是否已安装，版本需 >= 20.19.0。如果没装或版本不对，告诉我怎么装。
```

**你应该看到**：Claude Code 会执行 `node --version` 检查版本。如果已安装且版本符合，会直接告诉你"Node.js 已就绪"。如果没装或版本太低，它会根据你的操作系统给出对应的安装指南（浏览器下载、brew、winget 等）。

**如果出错**：

| 错误                                       | 原因          | 解决                                                                                               |
| ---------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------ |
| Claude Code 提示 "node: command not found" | Node.js 未安装 | 按照 Claude Code 给出的安装指引操作。Windows 用户访问 https://nodejs.org 下载 LTS 安装包；Mac 用户可用 `brew install node` |
| 版本低于 20.19.0                             | 需要升级        | Claude Code 会告诉你如何升级。通常去 nodejs.org 下载最新 LTS 覆盖安装即可                                              |
| 安装后 node 命令仍不可用                          | PATH 未刷新    | **Windows 用户**：关闭终端/命令提示符后重新打开，或重启电脑。**Mac 用户**：关闭终端后重新打开                                        |

### Step 2: 确认 Claude Code CLI

**执行方式**：Claude Code 对话

**你现在要做的是**：确认 Claude Code 已安装可用，并了解两个最常用的"原生能力"——Plan 模式（先计划后执行）和 Checkpoint（自动存档点）。它们不是第三方技能包，而是 Claude Code 自带的，后面写代码时天天用得上。

**在 Claude Code 中输入**：

```
请确认 Claude Code 正常工作：运行 claude --version 显示版本号，然后简单回复我"环境就绪"。
```

**你应该看到**：版本号（类似 1.x 或 2.x）+ 一句"环境就绪"。

> **两个原生能力（大白话）**：
> 
> - **Plan 模式**（按 Shift+Tab 切换）：Claude 只读代码、只写方案，不碰文件。大功能动手前先切到 Plan 模式让它出计划，你点头后再切回普通模式执行——相当于"先给 AI 戴上手铐再让它干活"。
> - **Checkpoint**：Claude 每次改代码前自动存档。改坏了随时说"回退到上一个存档点"，或者用 `/rewind` 撤销。跨天开发时它就是你最安全的后悔药。

### Step 3: 安装 OpenSpec 并初始化项目

**执行方式**：Claude Code 对话

**你现在要做的是**：安装 OpenSpec（规范驱动开发工具），用它初始化 ChemAI 项目的规格管理体系。

> **什么是 OpenSpec**：一个专为 AI 编程设计的规范驱动开发（Spec-Driven Development）工具。核心理念是"先约定再动手"——把需求编码为 Markdown 规格文件，人类和 AI Agent 在写代码之前先在规格上对齐。工作流：`/opsx:propose` 创建变更提案 → `/opsx:apply` AI 读规格生成代码 → `/opsx:archive` 完成后归档。

**在 Claude Code 中输入**：

```
帮我安装 OpenSpec：npm install -g @fission-ai/openspec@latest，装完后帮我验证是否安装成功。要求 Node.js >= 20.19.0。
```

安装成功后，继续在 Claude Code 中输入：

```
帮我在 ~/chemai-project/chemai-backend 目录下初始化 OpenSpec 项目：mkdir -p ~/chemai-project/chemai-backend && cd ~/chemai-project/chemai-backend && openspec init。初始化时选默认模板即可。
```

**你应该看到**：OpenSpec 会创建 `openspec/` 目录，结构如下：

```
openspec/
├── config.yaml     # 项目配置（含 context: 字段，自动注入每次规划请求）
├── specs/          # 当前规格（系统的事实来源，随变更归档逐步积累）
└── changes/        # 活跃的变更提案
    └── archive/    # 已完成的变更（归档后自动创建）
```

> **注意**：旧版 OpenSpec 用 `project.md` 存项目上下文，现已迁移为 `openspec/config.yaml`（更可靠，`context:` 字段会注入到每次规划请求）。如果你看到的目录里没有 `config.yaml`，让 Claude Code 执行 `openspec update` 生成。`specs/`、`changes/archive/` 也不是初始化时就建全的——第一次 propose 和 archive 时才会出现，这正常。

**验证**：

在 Claude Code 中输入：

```
请帮我确认 openspec/ 目录已创建，包含 config.yaml（specs/、changes/ 随使用生成）。然后跑一下 openspec list 看看有没有活跃变更。
```

`openspec list` 应显示当前没有活跃变更（空项目）。

**如果出错**：

| 错误                                                            | 原因              | 解决                                                                                                  |
| ------------------------------------------------------------- | --------------- | --------------------------------------------------------------------------------------------------- |
| `npm ERR! 404 '@fission-ai/openspec' is not in this registry` | npm registry 问题 | 告诉 Claude Code：`npm 找不到 @fission-ai/openspec，帮我试试社区镜像或者镜像源`                                         |
| `Node.js version mismatch` — 要求 >= 20.19.0                    | Node 版本过低       | 告诉 Claude Code：`我的 Node 版本低于 20.19.0，帮我升级`，Claude Code 会指导你从 nodejs.org 下载最新 LTS 覆盖安装               |
| `Permission denied`（Mac）                                      | 全局安装需要权限        | 告诉 Claude Code：`npm install -g 报 Permission denied，帮我处理`，Claude Code 会在命令前加 `sudo` 或指导配置 npm prefix |
| `openspec init` 提示 "directory not empty"                      | 当前目录已有文件        | 确保在空目录中运行。如需重来，告诉 Claude Code：`帮我把 ~/chemai-project/chemai-backend 删了重新创建`                          |

**Windows 注意**：强烈建议在 Git Bash 中开启 Claude Code 进行以上操作。`openspec` 命令在 Git Bash 中完全可用。

### Step 4: 安装 Gstack 技能包

**执行方式**：Claude Code 对话

**你现在要做的是**：安装 Gstack——一套 Claude Code 的技能包（slash commands），提供 50+ 个专用命令覆盖从规划到发布的全流程（数量以官方 `docs/skills.md` 为准）。

> **什么是 Gstack**：Garry Tan（YC 总裁）创建的 Claude Code 技能包。它把 Claude Code 变成一个"虚拟工程团队"——每个斜杠命令切换一个角色：
> 
> - `/plan-ceo-review` — CEO 视角的战略审查
> - `/plan-eng-review` — 工程经理的架构审查
> - `/review` — 代码审查
> - `/qa`、`/qa-only` — 浏览器自动化 QA 测试
> - `/ship` — 版本发布（合并+测试+changelog+PR）
> - `/retro` — 工程回顾
> - `/cso` — 安全审计
> - `/investigate` — 根本原因调试
> - 更多：`/browse`、`/design-html`、`/document-generate` 等共 50+ 个（数量随版本持续增长，以官方 `docs/skills.md` 清单为准）

**在 Claude Code 中输入**：

```
帮我安装 Gstack 技能包：clone https://github.com/garrytan/gstack.git 到 ~/.claude/skills/gstack/ 然后运行 setup 脚本。装完后帮我验证文件都在。
```

**你应该看到**：setup 脚本执行后，`~/.claude/skills/gstack/` 目录下会出现 50+ 个 SKILL.md 文件和其他配置（数量以官方仓库为准）。

**验证**：

在 Claude Code 中输入：

```
请在 Claude Code 中输入 / 查看自动补全列表，确认 Gstack 命令（/qa、/ship、/retro 等）已出现。
```

Claude Code 输入 `/` 后应该能看到 `/qa`、`/ship`、`/retro`、`/review`、`/plan-ceo-review` 等 Gstack 命令。

也可以让 Claude Code 直接验证文件：

```
帮我 ls ~/.claude/skills/gstack/ 看看有哪些文件，确认 Gstack 已安装。
```

**如果出错**：

| 错误                               | 原因                    | 解决                                                                                                                           |
| -------------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `git clone` 失败（网络问题）             | GitHub 不可达            | 告诉 Claude Code：`GitHub 连不上，帮我用 ghproxy 镜像 clone gstack`，Claude Code 会使用 `https://ghproxy.com/github.com/garrytan/gstack.git` |
| `./setup: Permission denied`     | 脚本没有执行权限              | 告诉 Claude Code：`setup 脚本没有执行权限，帮我 chmod +x 再跑`                                                                               |
| `./setup` 报错缺少 Bun               | Gstack 部分功能需要 Bun 运行时 | 告诉 Claude Code：`Gstack setup 需要 Bun，帮我装一下`，Claude Code 会执行 `curl -fsSL https://bun.sh/install                                |
| Claude Code 输入 `/` 看不到 Gstack 命令 | 安装路径不对或未重启            | 确认文件在 `~/.claude/skills/gstack/` 下，重启 Claude Code 后再试                                                                        |

**Windows 注意**：Gstack 在 Windows 的 Git Bash 中完全可用。Bun 在 Windows 上可能需要 WSL。如果 Bun 不可用，Gstack 的大多数 Skill 仍然可以通过 Claude Code 正常工作（只有少数需要 Bun 编译的功能受影响）。setup 脚本若在 Git Bash 中不执行，告诉 Claude Code：`帮我用 bash setup 命令运行 setup 脚本`。

### Step 4.3: 安装 no-mistakes 门禁（每次 push 的安全闸门）

**执行方式**：Claude Code 对话

**你现在要做的是**：安装 no-mistakes——一个独立的 pre-push 门禁工具。它会在你 `git push` 时自动跑一遍 review → test → docs → lint 流水线，全绿才把代码推上去。**从文档 43 起，每次推送都会用到它**（59 发布时做最终确认）。

> **大白话**：no-mistakes 是挡在"推送"前面的保安。AI 写的代码想推到远端，先过保安这一关；保安让另一个 AI 帮你复查、跑测试、查文档、查格式，全部通过才放行。它和 Gstack 是两套东西——Gstack 是"工程团队角色"，no-mistakes 是"推送闸门"。

**在 Claude Code 中输入**：

```
帮我安装 no-mistakes 门禁工具：先 curl -fsSL https://raw.githubusercontent.com/kunchenguid/no-mistakes/main/docs/install.sh | sh 安装，然后在当前项目里执行 no-mistakes init（它会自动在用户级安装 /no-mistakes 技能）。装完验证 no-mistakes --version 可用。
```

**你应该看到**：安装脚本输出 + `no-mistakes init` 提示 "Gate initialized" + 版本号。此后 `git push no-mistakes` 即可走门禁流水线。

**如果出错**：

| 错误                  | 原因       | 解决                                              |
| ------------------- | -------- | ----------------------------------------------- |
| 安装脚本下载失败            | 网络问题     | 告诉 Claude Code：`帮我用代理或镜像重试，或者用 go install 方式安装` |
| `no-mistakes` 命令找不到 | PATH 未刷新 | 关闭终端重新打开，或让 Claude Code 处理 PATH                 |

### Step 5: 创建项目骨架

**执行方式**：Claude Code 对话

**你现在要做的是**：让 Claude Code 帮你创建项目骨架。告诉它去哪读设计文档，产出四样东西：目录结构、CLAUDE.md（项目行为准则）、CONTEXT.md（领域词汇表）、DESIGN.md（前端视觉设计规范）。

**你应该看到**：Claude Code 会先逐份阅读设计文档（你会看到它在输出每份文档的摘要），然后基于读到的内容创建目录、CLAUDE.md、CONTEXT.md 和 DESIGN.md。整个过程大概需要 2-3 分钟。

**执行方式**：Claude Code 对话
