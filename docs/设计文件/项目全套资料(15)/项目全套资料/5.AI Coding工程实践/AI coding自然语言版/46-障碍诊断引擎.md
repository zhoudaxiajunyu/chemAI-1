### 核心架构

整个障碍诊断引擎采用**规则引擎 + LLM 混合诊断**架构。这一架构在 26 号设计文档中有完整定义（33 号文档提供对应数据模型），你需要让 Claude 在动手编码前先读完：

- **`D:\pm\课程资料\全套资料\4.产品设计\26-错题诊断与障碍分类系统设计.md`** -- 三维障碍分类模型（概念理解型/审题障碍型/表述障碍型）、混合型诊断架构（§3.1）、置信度分级与聚合计算（§6）。这是本阶段的"规格说明书"。
- **`D:\pm\课程资料\全套资料\4.产品设计\33-数据模型设计.md`** -- `BarrierType` 枚举定义（§八）、学生障碍画像字段（§9.1）、与 `StudentAnswer` 表的关联。

```
学生错题提交
      │
      ├──→ 规则引擎 ──→ 规则匹配结果
      │         │
      │   YAML规则基 + 模式匹配
      │   精确率 ~90%
      │
      ├──→ LLM 深度诊断 ──→ LLM 诊断结果
      │         │
      │   DeepSeek / MiMo-V2.5 + Few-shot Prompt（通过 OpenAI 兼容 API）
      │   召回率 ~85%
      │
      └──→ 置信度聚合引擎 ──→ 最终诊断 + 补救建议
                │
          加权评分 + 聚合计算
```

### 三大核心组件

| 组件 | 职责 | 设计文档出处 |
|------|------|-------------|
| **规则引擎** | 确定性模式匹配，覆盖关键词规则 | 26号文档：关键词规则库（§4.2）、匹配算法 |
| **LLM深度诊断** | 语义推理，识别规则库未覆盖的新模式 | 26号文档：Prompt 设计（§5）、输出格式规范（§5.5） |
| **置信度聚合** | 加权聚合两路输出，类别不一致时按分级处理 | 26号文档：置信度分级与聚合计算（§6.1/§6.2） |

**apply 过程中常见错误速查**：

| 错误 | 原因 | 解决 |
|------|------|------|
| YAML 解析错误（缩进/格式问题） | 缩进不一致（混用空格和 Tab） | 确保全部使用空格缩进，用 VS Code 渲染空白字符排查 |
| `ModuleNotFoundError: No module named 'yaml'` | PyYAML 未安装 | `pip install pyyaml` |
| 正则编译失败或匹配时 CPU 卡死 | 正则包含嵌套量词导致灾难性回溯 | 简化正则表达式，使用非贪婪量词，限制重复次数 |
| 规则引擎返回空结果 | 匹配阈值设置过高或关键词列表不完整 | 让 Claude 打印中间匹配过程调试，检查每条规则的关键词覆盖度 |
| 已知错误答案未被捕获 | 关键词不全或 anti_keywords 误排除 | 检查目标规则的关键词同义词覆盖，确认 anti_keywords 未误匹配 |
| LLM API 返回 401 | API Key 未配置或无效 | 检查 `.env` 中对应环境变量，确认 key 未过期 |
| LLM 返回非 JSON 格式 | API endpoint 配置错误或 LLM 未遵守输出格式 | 增加 JSON 预处理（提取 markdown 代码块中的 JSON），检查 `response_format` 参数 |
| JSON 解析成功但字段缺失 | Prompt 未严格约束输出 schema | 让 Claude 检查 System Prompt 中是否包含完整的输出格式定义 |
| API 调用超时 | 网络不稳定或 LLM 推理慢 | 增加 timeout 配置，或换用更快的模型 |
| Mock 测试通过但真实调用失败 | 环境变量/网络与 Mock 环境不同 | 日常开发仅运行 Mock 测试，真实 API 测试单独配置 |
| 聚合置信度超出 [0, 1] | clamp 逻辑缺失 | 在聚合计算的最后一步加上边界限制 |
| 两路诊断类别不一致 | 置信度分级与聚合权重设置不当 | 让 Claude 对照 26 号文档 §6.1/§6.2 的聚合策略逐条验证 |
| 默认值填充不一致 | 可选字段在聚合函数中未初始化 | 让 Claude 在聚合函数入口统一初始化所有输出字段 |
| 端到端测试置信度偏低 | 规则引擎匹配覆盖率不足 | 检查规则配置中该案例对应的关键词和正则是否充分 |

## 三、置信度聚合情景

聚合引擎的置信度聚合逻辑由 26 号设计文档定义。Claude 在 apply 阶段从文档中提取聚合规则并实现。核心情景包括：

- 两路高置信度且类别一致：直接输出
- 置信度一高一低：以高置信度那路为主
- 类别冲突：按置信度阈值决定采纳哪一路
- 双低置信度：标记"需人工审核"
- 仅单路有结果：按该路权重折算
