# 21. 页面流程与交互设计 -- ChemAI (智辅化学)

> 本文档以 Mermaid 流程图形式定义 ChemAI 三端（教师/学生/家长）的核心用户流程、跨端数据闭环以及基于用户故事的流程映射。本文档基于 [20-信息架构与导航设计](./20-信息架构与导航设计.md) 中定义的页面结构，为每个核心场景描述完整的用户操作路径和系统响应。

## 一、教师端核心流程

### 1.1 教师注册与入驻审批流程

以下为审批流程的完整步骤：

```mermaid
graph TD
  A[教师访问注册页] --> B[填写入驻申请<br/>姓名/学校/学科/资质证明]
  B --> C[提交申请 → 系统记录待审批]
  C --> D{管理员审核}
  D -->|通过| E[创建教师账号 + 分配角色]
  D -->|驳回| F[记录驳回原因 + 通知申请人]
  E --> G[系统生成教师账号<br/>teacher_id + 初始密码]
  G --> H[通知教师账号已开通]
  H --> I[教师首次登录 → 完善个人信息]
  I --> J[进入教师主面板]
```

**关键接口**:
- `POST /api/auth/apply` -- 提交入驻申请
- `POST /api/teacher-applications/{app_id}/approve` -- 审批通过
- `POST /api/teacher-applications/{app_id}/reject` -- 驳回申请
- `GET /api/teacher-applications` -- 管理员查看申请列表

### 1.2 答题卡 OCR 批改闭环

教师上传答题卡后，系统依次完成 OCR 识别、学生信息提取、答案比对和结果入库，并自动触发障碍诊断。

```mermaid
graph TD
  A[教师进入 OCR 页] --> B[选择班级 + 批量上传答题卡图片]
  B --> C[UploadSession 状态机启动<br/>→ processing]
  C --> D{文档解析引擎选择<br/>优先 MinerU<br/>降级 Baidu OCR}
  D --> E[并行提取学生信息<br/>学号/姓名/答案区域]
  E --> F[LLM 语义批改]
  F --> G[教师预览确认<br/>低置信度字符红色高亮<br/>置信度 < 70% 需人工复核]
  G --> H[教师修正并确认]
  H --> I[答案入库]
  I --> J[自动触发障碍诊断]
  J --> K[更新学生障碍画像]
  K --> L[生成班级统计数据]
```

**关键接口**:

- `POST /api/ocr/tasks/batch` -- 批量创建 OCR 任务
- `GET /api/ocr/tasks/batch/{batch_id}` -- 查询批次状态
- `POST /api/grading/run` -- 执行 LLM 语义批改
- `POST /api/grading/save` -- 保存批改结果
- `POST /api/diagnosis/run-llm/{exam_record_id}` -- 运行 LLM 障碍诊断

### 1.3 AI 出题 → 审核 → 题库 → 考试发布

教师通过出题工作台配置参数，AI 生成题目后经四维审核引擎校验，教师确认后入库并发布考试。

```mermaid
graph TD
  A[教师进入考试工作台 Tab1] --> B[设置出题参数<br/>知识点/难度/题型/题量]
  B --> C[AI 生成题目]
  C --> D{四维审核引擎检查<br/>1.系数配平 2.反应条件<br/>3.产物稳定性 4.分子结构}
  D -->|全部通过| E[题目标记审核通过]
  D -->|未通过| F[自动重生成 最多3次<br/>超限从题库替换]
  F --> C
  E --> G[教师确认并保存]
  G --> H[题目入库 + 自动向量检索匹配真题]
  H --> I[创建考试]
  I --> J[选择题目添加到考试]
  J --> K[发布考试]
  K --> L[学生端可见考试]
```

**关键接口**:
- `POST /api/question/generate` -- AI 生成题目
- `POST /api/question/audit` -- 四维审核
- `POST /api/question/{question_id}/approve` -- 教师确认入库
- `POST /api/question/similar` -- 向量相似真题匹配
- `POST /api/exam/create` -- 创建考试
- `POST /api/exam/{exam_id}/publish` -- 发布考试

### 1.9 学情预警 → 处理 → 归档

系统每日自动检测学生异常状态（连续未登录、成绩下滑、错题率过高），生成预警推送至教师端。教师查看预警详情后标记处理或忽略，处理后预警归档。

```mermaid
graph TD
  A[定时任务<br/>每日自动检测] --> B{预警服务<br/>检查所有学生}
  B --> C[检测条件1: 连续未登录<br/>≥3天无活跃记录]
  B --> D[检测条件2: 成绩下滑<br/>对比最近两次考试均分，下降≥10%]
  B --> E[检测条件3: 错题率过高<br/>最近一次考试错题率≥50%]
  C --> F[生成预警记录]
  D --> F
  E --> F
  F --> G[教师端查看待处理预警]
  G --> H[教师点击查看详情]
  H --> I[教师处理<br/>标记类型: 已联系/已关注/非学业原因]
  I --> J[预警归档<br/>1周内不重复触发同类型同学生]
  J --> K[可选: 通知推送到家长端]
```

**关键接口**:
- `GET /api/warning/pending` -- 查看待处理预警
- `GET /api/warning/student/{student_id}` -- 某学生全部预警
- `PUT /api/warning/{warning_id}/process` -- 处理/归档预警
- `POST /api/warning/check` -- 手动触发预警检查
- `POST /api/notification/send-to-parent/{student_id}` -- 通知推送家长

## 二、学生端核心流程

### 2.1 登录与首次

学生通过学号和密码登录。首次登录展示功能介绍引导（3 屏滑动），完成后进入 AI 助教对话页并加载对话历史。

```mermaid
graph TD
  A[学生访问登录页] --> B[输入学号 + 密码]
  B --> C[提交登录请求<br/>persona=student]
  C --> D{JWT 验证}
  D -->|失败| E[提示错误 + 重试]
  D -->|成功| F[返回 access_token<br/>+ student_id + persona]
  F --> G{是否首次登录}
  G -->|是| H[显示首次引导<br/>功能介绍 3 屏滑动<br/>+ AI 对话基本操作教学]
  H --> I[进入 AI 助教对话页]
  G -->|否| I
  I --> J[加载对话历史]
  J --> K[渲染快捷芯片<br/>实验 / 讲解 / 配平]
```

**关键接口**:
- `POST /api/auth/login` -- 学生登录
- `GET /api/auth/me` -- 获取当前用户信息
- Agent 对话流: `POST /api/agent/chat/langgraph/stream` (SSE, persona=student)

---

### 2.2 AI 辅导对话 (苏格拉底式启发教学)

学生在对话页输入化学问题后，Agent 识别辅导意图并调用对应的苏格拉底式辅导模块——离子方程式/配平/氧化还原等 7 个方向，分步引导不直接给出答案。

```mermaid
graph TD
  A[学生在对话页输入化学问题] --> B[Agent 意图分类<br/>识别辅导意图]
  B --> C[调用对应辅导功能模块]
  C --> D{辅导类型}
  D -->|离子方程式| E[离子方程式分步引导]
  D -->|化学方程式配平| F[配平分步引导]
  D -->|氧化还原| G[氧化还原分步引导]
  D -->|化学计量| H[化学计量分步引导]
  D -->|化学平衡| I[平衡分步引导]
  D -->|元素周期律| J[周期律分步引导]
  D -->|有机化学| K[有机推断分步引导]
  D -->|通用辅导| L[通用化学辅导]
  E --> M[返回引导步骤<br/>分步提问, 不直接给答案]
  M --> N[SSE 流式返回每个步骤<br/>学生逐步回答]
  N --> O{学生回答正确}
  O -->|是| P[进入下一步]
  O -->|否| Q[给出提示 + 引导重新思考]
  Q --> N
  P --> R{所有步骤完成}
  R -->|否| N
  R -->|是| S[总结知识点 + 关联同类题]
```

**设计原则**:
- 苏格拉底式对话: Agent 绝不允许直接给出最终答案
- 引导策略: 确认已知条件 → 分析解题思路 → 分步引导计算 → 学生自答每步 → 汇总
- Text Dedup: 当辅导模块已在工具返回中给出了 guidance/steps，系统抑制 LLM 对引导文本的复述

> **设计说明**：辅导功能的具体工具定义、SSE 事件协议、Text Dedup 算法详见 [29-Agent对话系统设计](./29-Agent对话系统设计.md)。

### 2.3 完成练习 → 查看结果 → 错题入本

学生进入练习页查看任务列表，逐题作答后提交。答对给予正面反馈，答错先提示审题再展开解析。全部完成后显示练习小结，错题自动入错题本。

```mermaid
graph TD
  A[学生进入练习页] --> B[查看任务列表<br/>待完成/已完成]
  B --> C[开始练习]
  C --> D[逐题作答<br/>选择题/填空题]
  D --> E{提交答案}
  E --> F[即时判分<br/>返回正确/错误]
  F --> G{答案正确}
  G -->|是| H[绿色对号 + 正面反馈]
  G -->|否| I[先提示审题<br/>&#34;再想一次?&#34;]
  I --> J{学生选择}
  J -->|我想想| D
  J -->|我不懂| K[展开完整解析]
  H --> L{还有题目?}
  L -->|是| D
  L -->|否| M[练习小结<br/>正确率 + 知识点表现]
  K --> L
  M --> N[错题自动进入错题本]
  N --> O[更新学生画像<br/>知识点掌握度重新计算]
```

**关键接口**:
- `GET /api/practice/student/{student_id}/tasks` -- 练习任务列表
- `GET /api/practice/student/{student_id}/practice/{practice_id}` -- 练习详情
- `POST /api/practice/submit` -- 提交答案
- `GET /api/practice/history/{student_id}` -- 练习历史-防注入（2026、）

### 2.5 间隔复习 → 升级/降级

复习任务到期后提醒学生进入复习中心。逐题作答后系统根据本轮正确率升降级——连续正确则延长间隔，连续错误则缩短间隔并补充学习资源。

```mermaid
graph TD
  A[复习任务到期提醒] --> B[学生进入复习中心]
  B --> C[查看待复习题目]
  C --> D[逐题作答]
  D --> E[提交复习结果]
  E --> F{本轮正确率}
  F -->|≥80%| G[升级 review_level++<br/>下次间隔延长<br/>1d → 3d → 7d → 14d → 30d]
  F -->|<50%| H[降级 review_level--<br/>3天后追加补救轮]
  F -->|50%-80%| I[保持 review_level<br/>按标准间隔]
  G --> J[consecutive_correct++]
  H --> K[consecutive_errors++]
  J --> L{consecutive_correct ≥ 3}
  L -->|是| M[标记知识点已掌握<br/>停止推送该题]
  L -->|否| N[继续下一轮]
  K --> O{consecutive_errors ≥ 3}
  O -->|是| P[降级 + 推送学习资源推荐]
  O -->|否| N
```

**关键接口**:
- `GET /api/review/student/{student_id}/due` -- 到期复习任务
- `GET /api/review/student/{student_id}/count` -- 待复习计数
- `POST /api/review/submit` -- 提交复习结果
- `POST /api/review/sync/{student_id}` -- 同步复习计划

## 四、跨端数据闭环

以下时序图展示一次完整的"教师出卷 → 学生答题 → 自动诊断 → 教师查看 → 家长接收"数据流:

教师发布考试-写入数据库-学生端可见-学生作答提交-agent即时判分-后台异步出发障碍诊断-更新学生的障碍画像-老师查看班级统计-定时任务生成家长周报-给家长推送信息-家长查看信息-家长AI解读

从教师发布考试到家长查看子女学习报告，数据在三端之间形成完整闭环，每个角色在闭环中获取所需信息。

```mermaid
sequenceDiagram
  actor T as 教师
  actor S as 学生
  actor P as 家长
  participant API as ChemAI API
  participant DB as 数据库
  participant Agent as LangGraph Agent
  participant Scheduler as 定时调度器

  T->>API: POST /api/exam/create
  API->>DB: 写入 ExamRecord(status=draft)
  T->>API: POST /api/exam/{id}/questions
  API->>DB: 写入 QuestionExamLink
  T->>API: POST /api/exam/{id}/publish
  API->>DB: 更新 ExamRecord(status=published)

  Note over S,API: 学生端答题
  S->>API: GET /api/practice/student/{sid}/tasks
  API->>DB: 查询 PracticeAssignment
  S->>API: POST /api/practice/submit
  API->>DB: 写入 StudentAnswer(is_correct, barrier_type, ...)
  API-->>S: 即时判分结果

  Note over API,DB: 自动触发异步诊断
  API->>Agent: 触发障碍诊断
  Agent->>Agent: LLM 分析答案 → 判定障碍类型
  Agent->>DB: 更新 Student.barrier_type<br/>写入 DiagnosisResult

  Note over T,API: 教师查看班级统计
  T->>API: GET /api/panel/class/{cid}
  API->>DB: 查询 StudentAnswer + DiagnosisResult
  API-->>T: 班级概览 + 障碍分布 + 成绩趋势

  Note over Scheduler,P: 定时任务生成家长周报
  Scheduler->>API: 每日/每周定时触发
  API->>Agent: 生成家长报告
  Agent->>DB: 查询答题记录 + 障碍 + 练习日志
  Agent-->>API: 家长版周报 (通俗中文)
  API->>DB: 写入 ParentNotification(type=weekly_report)
  API->>P: 推送通知

  P->>API: GET /api/parent/notifications
  P->>API: GET /api/parent/child/{sid}/weekly
  API-->>P: 周报内容
  P->>API: POST /api/parent/child/{sid}/report/ai-summary
  API->>Agent: 家长角色 Agent 解读
  Agent-->>API: SSE 流式 AI 解读
  API-->>P: 通俗中文解读
```

**核心数据写操作顺序**:
1. `ExamRecord` (考试发布) → 教师创建并发布考试
2. `StudentAnswer` (学生答题) → 学生提交答案时写入，含正确性和障碍类型
3. `Student.barrier_type` (学生障碍) → LLM 诊断后更新
4. `ParentNotification` (家长通知) → 定时任务触发，含周报/预警摘要
