## 三、设计递进关系

本部分文档按**从0到1的设计递进顺序**组织，每层设计建立在前面各层决策之上：

```
第1层（结构）：20-信息架构 → 定义页面结构和导航关系
  ↓
第2层（流程+权限）：21-页面流程 + 22-权限体系 → 定义用户如何操作、谁能操作什么
  ↓
第3层（业务系统）：23-28 → 六大业务模块的独立设计，消费第2层产出的流程和权限约束
  ↓
第4层（Agent）：29-Agent对话系统 → 定义AI如何串联所有业务能力，工具集在此定义
  ↓
第5层（数据+质量）：30-学情分析 + 31-评测体系 → 消费业务和Agent的产出进行分析
  ↓
第6层（支撑）：32-家长端 → 基于前述所有系统为家长提供数据视图
  ↓
第7层（技术落地）：33-数据模型 → 34-API → 35-设计系统 → 36-桌面应用 → 37-技术选型
  ↓
第8层（前端整合+验证）：38-前端页面设计规格 → 将散落在各文档的前端设计集中为14页完整规格；41-原型验证 → 用HTML原型验证设计可行性
```

> **阅读原则**：每份文档只包含该设计阶段能够做出的决策。后面的文档可以引用前面的决策，但不能反过来。

## 四、与 PRD 的关系

本部分（第四部分）与 `PRD-智辅化学-Agent产品需求文档.md`（项目根目录）互补：

- **PRD** 回答 "What"：产品是什么、有哪些模块、什么状态

PRD 是产品的高层定义，本部分是落地的详细设计规格。
